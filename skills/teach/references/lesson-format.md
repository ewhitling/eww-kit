# Standalone lesson format

Write one useful Markdown note, not a fixed-length essay. Keep sentences short and define terms before using them.
Use destination frontmatter and authorship conventions rather than introducing a new vault schema.

A useful default structure is:

1. **Title:** name the concept or question clearly.
2. **Authorship:** mark the generated content as the destination contract requires.
3. **Why it matters:** the problem the concept solves and the lesson's scope.
4. **How it works:** foundations and the few steps that connect them.
5. **Worked example:** one concrete case with assumptions and units where relevant.
6. **Limits:** when the explanation or method does not apply, if material.
7. **Try it:** one optional prediction, application, or retrieval question.
8. **Sources:** verified links supporting the important claims, when sources were used.

Combine or omit headings when that makes a short lesson clearer.
Include a Mermaid diagram beside the explanation it supports only when the relationship benefits from it.
Label illustrative values as fictional. Put any answer to the practice question after the question,
with a clear Answer label, so readers can try first. Do not present invented user responses as learning progress.

Use ordinary Markdown links. Use wiki links only when the approved destination already uses them
and the target exists or the user has approved the intended convention.
Do not invent citations, tags, lesson numbering, learning records, or a daily-note location.

For existing notes, this structure guides only the approved new section. Preserve the surrounding document.
